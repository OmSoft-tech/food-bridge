# Фуд-мост — техническая спецификация MVP

Конкурсная работа X5 «Вайбкодинг добрых дел». Направления: сокращение пищевых
отходов (ритейл) + помощь благополучателям продуктового фонда.

## Суть

Статическое одностраничное веб-приложение без бэкенда: витрина продуктовых
излишков магазинов, витрина нужд пунктов помощи, автоматический мэтчинг передач
и калькулятор покрытия — на сколько человек и на сколько дней хватит передачи.

## Стек

- React 18 + Vite + TypeScript (strict)
- Стили: обычный CSS (один файл, CSS-переменные), без UI-библиотек
- Данные: статические JSON-моки в `src/data/` (магазины, излишки, нужды, нормы)
- Сборка: `npm run build` → статика, деплой на GitHub Pages через GitHub Actions
- Интерфейс полностью на русском, тёмная «эко»-тема (зелёный + графит)

## Структура данных (моки, реалистичные, на 3 сети × 6 магазинов, 4 пункта помощи)

1. `products.json` — справочник товаров: id, название, категория (мясо/молочка/
   бакалея/овощи/хлеб/консервы), единица, вес единицы кг, срок хранения дней.
2. `surpluses.json` — излишки магазинов: id, магазин, товар, количество,
   дата/срок годности, статус (доступно/зарезервировано/передано).
3. `needs.json` — нужды пунктов помощи: id, пункт, товар, желаемое количество,
   приоритет (высокий/средний).
4. `stores.json` / `recipients.json` — магазины и пункты помощи (название,
   адрес, округ города).
5. Нормы: в `src/lib/nutrition.ts` — константы «человеко-день» по категориям
   (кг/чел/день) для расчёта покрытия.

## Функциональность (4 экрана-вкладки + дашборд сверху)

1. **Дашборд** — сводка: всего излишков (кг), совпадает с нуждами (%),
   человеко-дней покрытия, избегнутых списаний; мелкая разбивка по категориям.
2. **Излишки** — таблица/карточки излишков с фильтром по категории, сети и
   сроку годности (сортировка по «скорее испортится»).
3. **Нужды** — карточки пунктов помощи с прогрессом закрытия потребности.
4. **Мэтчинг** — кнопка «Подобрать передачи»: жадный алгоритм — сортировка
   излишков по сроку годности, закрытие нужд по приоритету, показывает план
   передач (магазин → пункт, состав, кг, покрывает N чел × M дней) со статусами
   (запланировано/подтверждено). Кнопка «Сбросить».
5. **Калькулятор** — набор из товаров (добавить позиции), бюджет условный:
   показывает суммарный вес, калорийность и «покроет X человек на Y дней»
   по нормам; готовая раскладка по категориям.

## Нефункциональные требования

- Работает без сервера: только статика, все интеракции локальные.
- Мобильная вёрстка (медиа-запросы) — жюри может открыть с телефона.
- README.md: назначение, скриншот-плейсхолдер, «как запустить», описание
  пользы (для Фонда и для ритейла), стек.
- Лицензия MIT, .gitignore для node_modules/dist.
- Коммиты осмысленные, по ходу работы.

## Явно не входит в MVP

- Регистрация/авторизация, реальные API, карты, push-уведомления.
- i18n кроме русского.
